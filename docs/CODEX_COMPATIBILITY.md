# Codex CLI compatibility (contract spike)

Verified October 16, 2026 with installed `codex-cli 0.163.0` on Windows, plus the official [CLI reference](https://developers.openai.com/codex/cli/reference/) and [non-interactive guide](https://developers.openai.com/codex/noninteractive/). This is a CLI contract observation, not a claim of Mycelink Codex support.

- `codex exec --json --cd <directory> --sandbox read-only -` accepts a prompt on stdin, emits JSONL to stdout, and exits 0 on a successful authenticated turn. `--model`, `--output-schema <file>`, and `--output-last-message <file>` are exposed by `codex exec --help`; schema-constrained final output and the last-message file were verified live. `workspace-write` is an advertised sandbox mode; avoid `danger-full-access` and `--dangerously-bypass-approvals-and-sandbox`.
- `--ask-for-approval`/`-a` appears on top-level `codex --help` but **not** on `codex exec --help`; `codex exec -a never` exits 2 (`unexpected argument '-a'`). Use the explicit `-c approval_policy=never` override in non-interactive exec; the CLI parses an unquoted TOML value as a literal. Quoted `approval_policy="never"` was accepted in Git Bash but rejected by Mycelink's Windows batch-shim safety policy. Never silently omit approval policy or turn off the sandbox.
- The observed success sequence was `thread.started`, `turn.started`, `item.completed` (`item.type=agent_message`, `item.text`), `turn.completed` (`usage.input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_output_tokens`). The observed isolated unauthenticated invocation produced `error` retries and `turn.failed` carrying an HTTP 401 message; exit 1. Fixture values are sanitized/synthetic.
- On Windows npm installs provide a `codex.cmd` shim and a bash `codex` shim. Native `spawnSync('codex')` did not resolve the executable; use the repository's `planCommand` batch-shim handling for `codex.cmd`. The live test probes this path with `planCommand`.
- Cancellation and tool event payloads, workspace-write enforcement, and plugin hooks are not yet certified by this spike. They require isolated fake and live integration tests before native-host parity can be claimed. An unauthenticated isolated `CODEX_HOME` cannot verify authenticated success; the opt-in test uses whichever profile the tester explicitly elects to run it with.
