# Experimental WSL generation-bound broker contract

`PolicyBroker(root, claim, generation, allowed_paths, current, hook_ready)` is constructed **only by a trusted root controller**. The root directory is an absolute root-owned non-replaceable directory; the worker/reviewer roles map to distinct provisioned Linux UIDs obtained through `SO_PEERCRED`, not a JSON `role` claim. The broker serializes submissions, denies root or unknown principals on the socket, requires exact canonical case-unique file paths, rechecks live claim and hook predicates before validation, before sealing, and after sealing, and creates independently root-owned `worker/result.json` and `reviewer/verdict.json` slots using `wsl-codex-policy.py`. No broker endpoint, exception, or callback failure means no authorization. The socket test endpoint is **experimental only**: the isolated worker never mounts it in the current launcher path.

`consume_transport(transport_root, role)` is the separate trusted-controller ingestion interface for the launcher transport. The controller supplies the expected role from its launch record; this method pins root-private claim/generation directories, rejects missing/partial/symlinked or nonprivate pending/final publications and stale identity, then applies the same validation and sealing. A root-only launcher publication is not a grant to run gates or apply files. The transport's `source_files` field is untrusted metadata here; the controller must verify it against the exact immutable manifest and source snapshot recorded for this claim. Do not infer source authority from the envelope or allow it to expand `allowed_paths`.

**Integration obligations before production dispatch:** bind both predicates to the Orchestrator's actual current claim ID, generation, worktree/base SHA, and hook registration under the same controller-owned lifecycle lock that guards claim revocation and final slot consumption. A callback that merely checks a mutable Boolean without that lock has a remaining revoke/accept race after the final check. Terminate and reap the old process tree before rotating generations; never reuse a pending transport reservation or a role slot. Derive exact allowed file names from the trusted repository policy/forbidden precedence, not the worker's prompt, tool/MCP args, hook assertion, or `source_files`. Ensure the controller checks sealed receipt hashes and independently runs exact TDD/gate/commit/settle operations; neither this broker nor `wsl-codex-policy.py` authorizes those operations. Reject any result/verdict missing the expected schema or generation. Preserve the unconditional Codex preflight DENY until that integration and independent whole-process adversarial review pass. The existing Claude path is untouched.

This broker assumes the trusted root controller, root-owned launcher, transport and broker root cannot be modified by a hostile Windows host account, root process, or a concurrently writable source tree; those are outside its isolation claim. `SO_PEERCRED` attests the Linux UID, not an individual process: all descendants under the same role UID are equally hostile and can race each other, so the isolated worker must have no privileged host paths, credentials, or broker-mounted controller socket. The root-only ingestion is the intended launcher handoff. A hostile worker's proposal contents are data, never an instruction to execute. Failures in downstream apply/reconcile remain fail-closed responsibilities of the trusted controller.
