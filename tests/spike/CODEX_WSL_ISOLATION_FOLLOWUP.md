# WSL standalone Codex boundary: follow-up negative spike

**Historical verdict for this mount-only probe: NO-GO for activation (October 17, 2026).** This disposable probe predates the separately authorized WSL worker, broker, transport and scoped API bridge; its negative FD/hardlink findings remain reproducible for unsafe modes, but its missing-infrastructure and missing-login statements below are historical, not current blockers. The separate `wsl-*.test.py` suites have since exercised authenticated Linux Codex and constrained descendants. The production Codex preflight remains DENY because Orchestrator claim/gate/git/TDD/settle wiring and independent adversarial acceptance are unfinished. Read alongside `docs/CODEX_COMPATIBILITY.md` and the original `.hermes/plans/2026-10-16_155306-mycelink-codex-support.md`; do not modify that plan.

## Reproduce on this host

From the repository root in Windows Git Bash:

```sh
wsl.exe -d Ubuntu -u psh09 -- bash /mnt/c/Users/psh09/mycelink-history-rewrite/tests/spike/codex-wsl-isolation-followup.sh inherited  # EXPECT EXIT 1: intentional FD escape
wsl.exe -d Ubuntu -u psh09 -- bash /mnt/c/Users/psh09/mycelink-history-rewrite/tests/spike/codex-wsl-isolation-followup.sh closed     # EXPECT EXIT 0: shell-only partial fence
wsl.exe -d Ubuntu -u psh09 -- npx --yes @openai/codex@0.163.0 login status
```

`inherited`: `/worktree` is read-only, `/proposal` is private tmpfs, `/mnt/c` and `/init` are unmounted, net is unshared, but launcher FD 9 opens a protected file. **Observed** `fd9_visibility=VISIBLE`, `fd9_write=0`, `fd_target_size=6`, `probe_assertion=FAILED_inherited`, while direct and hardlink-alias pathname writes are denied (`alias_write=2`, `normal_write=2`, `direct_write=2`). This is a real write across the mount boundary, not a model assertion. The worker printed `spoofed_review=approved`; its stdout is untrusted and must never become a reviewer verdict. Bash/POSIX output file descriptors 1 and 2 themselves also need scrutiny if they are connected to privileged channels.

`closed`: a *demonstration* launcher closes FDs 3–1023 before `execvp(bwrap)`; observed `fd9_visibility=HIDDEN`, `fd9_write=2`, `fd_target_size=0`, protected and source files unchanged, `proposal_write=0` inside tmpfs but `proposal_persisted=NO` after exit. `/proc/1/comm` is `bwrap` (namespace-local PID 1), `/mnt/c` and `/init` are hidden, and curl failed with exit 6 in the isolated net namespace. This proves only these particular shell actions, not a complete process/channel contract. The `closerange(3, 1024)` example is **not** a complete descriptor sweep: a real launcher must close all unapproved handles irrespective of maximum FD, sanitize inherited stdio/environment, and test Windows↔WSL transport, pipe and credential channels. The intentionally failing negative mode is kept executable to prevent a mount-only safety claim.

Both modes print `unavailable_broker=DENY_BEFORE_PAYLOAD` and `failed_broker=DENY_BEFORE_PAYLOAD` from an illustrative shell check; this is **not** proof that any Mycelink/Codex production launcher currently performs those checks, nor that a hook failure denies a Codex tool. In a worker with no available hook callback, the shell actions bypass it entirely; the mount boundary denied path writes in `closed` mode but the inherited FD defeated it in `inherited` mode. At the time of this *older probe*, Ubuntu `psh09` `npx --yes @openai/codex@0.163.0 --version` returned `codex-cli 0.163.0`; `login status` returned `Not logged in` (login was subsequently provisioned and authenticated isolated turns have passed via the scoped bridge). `command -v codex` resolves the Windows npm shim under `/mnt/c/...` and that shim lacks the Linux optional binary; use a Linux install, as `codex-wsl-probe.sh` did. Previous opt-in test in `tests/spike/codex-wsl-boundary.test.ts` is intentionally RED on a writable bind with a hardlink to an unmounted protected result; private tmpfs changes do not persist. The prior isolated `codex exec` produced `thread.started,turn.started` but no authenticated completion.

## Historical proposed launch contract — partial later implementation, no activation

1. Trusted Windows controller freezes a per-claim generation, node identity, canonical source snapshot, allowed-path policy and expected result slot. Launch exactly one **Linux** Codex `exec` via `wsl.exe -d Ubuntu -u <dedicated-worker> -- <fixed Linux launcher>`, never a Windows npm shim or an agent-chosen shell. That launcher requires a trusted immutable manifest, installed Linux bwrap/Codex, an already available broker, a scoped API-egress/auth bridge, and verified namespace setup; any missing or failed prerequisite, worker nonzero exit, broker crash, interrupted generation, or malformed output must produce **denial**, not fallback to host-native Codex. Existing provider preflight stays disabled until end-to-end evidence exists.
2. Isolate the **entire Codex process and every subprocess/MCP server** under `bwrap --unshare-all --new-session --die-with-parent` with fixed read-only system binaries and immutable per-claim source snapshot, private `/tmp`, `/home`, `/proc`, `/dev`, anonymous writable proposal area, no `/mnt/c`, `/init`, host sockets, WSL auth directory, or inherited writable descriptors. Network is absent except for a separately proven, narrowly scoped API service; generic `--share-net` fails the side-effect requirement. Keep output proposal private until the trusted broker validates and applies it through independently owned, race-safe handles; a direct writable bind into the protected result/worktree is unsafe. The trusted broker must NOT execute model-selected arbitrary commands.
3. Controller and reviewer must be **separate principals/capabilities** from the worker. Bind broker requests out-of-band to launch PID/claim/generation/role; never trust prompt, MCP arguments, hooks, JSONL, stdout, or reviewer text as identity. Controller-owned slots require compare-and-swap generation and ownership checks, an allowed-path merge that rejects symlink/hardlink/cross-filesystem aliases and directory swaps, and independent reviewer evidence. Terminate and reconcile all descendant processes before accepting any result. These are requirements, not tested accomplishments.

## What this cannot establish

- This historical probe had no authenticated turn or scoped egress; later isolated worker/bridge tests did. Previous no-net exec timed out, whereas sharing WSL net allowed unrelated `example.com` egress (`docs/CODEX_COMPATIBILITY.md`). Do not revive `--share-net`.
- No real Codex hook failure/timeout/bypass, MCP crash, built-in patch, hosted tool, or any production policy-broker enforcement. Official hooks document opt-out paths and error cases that continue; permission profiles apply to local commands but not all other surfaces. An illustration with `/bin/false` does not substitute for such a test.
- No immutable snapshot/proposal *transport* or race-safe apply implementation; no allowed_paths, role separation, result/reviewer ownership or TOCTOU proof against the actual Mycelink claim flow; no FD sweep of all possible descriptors, host-opened Unix sockets, pidfd/proc escape, or Windows-controller attack resistance. Windows can access WSL files by `\\wsl$` and Windows drives are normally mounted in WSL: the host launcher/controller is in the trusted computing base, not isolated by this probe.
- WSL2 bubblewrap Linux mount/PID/net observations are **not Windows desktop parity**.

**Current recommendation:** keep both native-Windows and WSL Codex dispatch disabled. The dedicated WSL worker identity, scoped auth/API bridge, snapshot/proposal transport and broker now have bounded opt-in tests, including real Codex; they are not yet connected to the real Orchestrator claim/gate/git/TDD/settle lifecycle or independently accepted as a complete boundary. Ubuntu login and authorization for scoped bridge use were subsequently supplied; do not ask for either again, open general networking, or copy Windows credentials.
