# Experimental WSL Codex lifecycle gate (NOT dispatch authorization)

`src/state/codex-lifecycle.ts` supplies a distinct cross-process mutex for an explicitly opted-in feature. The existing `STATE.json.lock` keeps its 120-second stale-owner semantics for Claude; the Codex mutex never steals an aged **live** owner. An orphaned primary owner can be recovered under a serialized recovery guard; a live reused PID is distinguished by the recorded OS process start identity when the OS can prove it. Unknown/unreadable/foreign owners and an orphaned recovery guard fail closed (operator intervention required, not automatic deletion). The opt-in marker is created only by trusted controller code before any experimental WSL use. Production preflight/adapter selection still reject Codex.

On opted-in features, `mutateState` and the checkpoint-restore `saveState` path acquire this mutex **before** the ordinary state lock. This includes the state mutations made by claim, cancel, resume and settle. `inspectWslCodexClaim` inspects under both locks; it is a diagnostic, not an execution grant. `withLiveWslCodexClaim` takes the lifecycle mutex, rechecks the exact live claim, lease, epoch, lineage, expiry and graph paths, then runs a *synchronous trusted callback* while keeping that mutex. A cross-process CLI cancellation was observed blocked until the callback ended; after cancellation the old generation was refused. An opt-in real Windows claim/WSL worker/transport/broker tracer ran inside that critical section. The tracer's Python broker still uses test-only `current=lambda: True` and `hook_ready=lambda: True` because the Windows controller owns the lock in this test; it is **not** an independent live predicate for arbitrary broker invocations.

**Not yet implemented:** durable WSL process revocation at cancel or lease expiry, finite renewable per-turn bridge capability with heartbeat/usage reconciliation, root-controller binding of broker ingestion to authenticated live predicates, transactional application with trusted gates/Git/TDD/history, genuine result and independent reviewer ingestion/settlement, and fully tested crash recovery of the *entire* transaction. The lock alone does not prove safety if unrelated filesystem operations, hooks or bridge requests occur outside its scope. No standalone script may be invoked as a production worker based on this tracer. A final adversarial reviewer must approve the entire integrated path before lifting the unconditional dispatch denial.
