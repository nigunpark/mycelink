# Experimental WSL Codex lifecycle gate (NOT dispatch authorization)

`src/state/codex-lifecycle.ts` supplies a distinct cross-process mutex for an explicitly opted-in feature. The existing `STATE.json.lock` keeps its 120-second stale-owner semantics for Claude; the Codex mutex never steals an aged **live** owner. An orphaned primary owner can be recovered under a serialized recovery guard; a live reused PID is distinguished by the recorded OS process start identity when the OS can prove it. Unknown/unreadable/foreign owners and an orphaned recovery guard fail closed (operator intervention required, not automatic deletion). The opt-in marker is created only by trusted controller code before any experimental WSL use. Production preflight/adapter selection still reject Codex.

On opted-in features, `mutateState` and the checkpoint-restore `saveState` path acquire this mutex **before** the ordinary state lock. This includes the state mutations made by claim, cancel, resume and settle. `inspectWslCodexClaim` inspects under both locks; it is a diagnostic, not an execution grant. `withLiveWslCodexClaim` takes the lifecycle mutex, rechecks the exact live claim, lease, epoch, lineage, expiry and graph paths, then runs a *synchronous trusted callback* while keeping that mutex. A cross-process CLI cancellation was observed blocked until the callback ended; after cancellation the old generation was refused. An opt-in real Windows claim/WSL worker/transport/broker tracer ran inside that critical section. The tracer's Python broker still uses test-only `current=lambda: True` and `hook_ready=lambda: True` because the Windows controller owns the lock in this test; it is **not** an independent live predicate for arbitrary broker invocations.

**Bounded cancellation tracer (not launch integration):** `scripts/wsl-codex-process.py` has a root-private, feature-token and claim/generation-bound WSL PID/starttime registry. Its `run` verb reserves an irreversible generation before starting a dedicated Linux process group, publishes a readiness receipt, and kills a child if registration fails. `revoke` checks all root-owned slots and process identities before signalling the groups, then waits for supervisor acknowledgement. An opted-in Windows `feature cancel` now holds the Codex lifecycle mutex, requires confirmed WSL revocation **before** changing STATE, and refuses to report success on malformed registry evidence or a failed WSL call. Live tests observed a Linux process die across the Windows/WSL boundary and a corrupted record leave the claim unchanged. This tracer does **not** establish a secure launch: the Orchestrator does not yet start a model+bridge under this registry or hold its mutex through an authenticated readiness handshake. A killed supervisor, escaped descendant, incomplete bridge HTTP request, or interrupted cancellation still needs a whole-transaction recovery protocol.

**Not yet implemented:** controller-owned immutable Git object source freezing and same-generation registered Codex launch; durable WSL process/bridge revocation at **all** cancel, resume, expiration and crash paths (the bridge now refuses new requests after a bounded 300-second maximum lease or trusted in-process revoke, but its admitted HTTP is not stopped by a separate controller); renewable authenticated heartbeat/usage reconciliation, root-controller binding of broker ingestion to authenticated live predicates, transactional application with trusted gates/Git/TDD/history, genuine result and independent reviewer ingestion/settlement, and fully tested crash recovery of the *entire* transaction. The lock and cancellation tracer alone do not prove safety if unrelated filesystem operations, hooks or bridge requests occur outside their scope. No standalone script may be invoked as a production worker based on these tracers. A final adversarial reviewer must approve the entire integrated path before lifting the unconditional dispatch denial.
