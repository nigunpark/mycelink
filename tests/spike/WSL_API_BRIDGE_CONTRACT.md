# Experimental WSL Codex API bridge contract

The trusted WSL controller starts `scripts/wsl-codex-api-bridge.py` **outside** the isolated worker namespace, with a private AF_UNIX socket (worker UID/GID), a controller-selected claim/generation/model, and `--max-output-tokens` plus `--total-output-tokens`. A worker-local loopback relay connects only to that socket; its network namespace is unshared (`--unshare-all`, never `--share-net`). The socket peer UID is checked with `SO_PEERCRED`; all children/MCP processes under that UID are hostile and share its capability. The worker receives only a placeholder API key. Neither the original WSL login nor the trusted service's token is mounted in the worker.

Only `POST /v1/responses` with JSON is forwarded. The bridge ignores caller Authorization/Cookie/Host, rejects unknown top-level request fields, disallows hosted tools, pins the model, injects or bounds `max_output_tokens`, and atomically reserves request bytes/count and maximum *requested* output tokens across connections. Reservations are not refunded on HTTP or upstream failures. The trusted upstream reads the owner-only regular login via `O_NOFOLLOW` and the same verified fd, and itself selects HTTPS `chatgpt.com` and `/backend-api/codex/responses`; it does not follow redirects. It forwards no upstream cookies/redirect headers and accepts only JSON or event-stream Content-Type. This is a *transport and request ceiling*, not attested actual token usage or a currency/spend guarantee: the trusted Orchestrator must independently settle usage from verifiable provider records and enforce a claim-wide budget. The bridge additionally has a monotonic finite request-admission lease of at most 300 seconds (`--lease-seconds`, default 300); expiry and trusted in-process `revoke()` prevent any *new* upstream reservation, with no refund. This does not terminate an already admitted in-flight HTTP request or implement cross-process CLI cancel/heartbeat: the Orchestrator must kill/revoke the service with the claim and reconcile any outstanding request.

Adversarial coverage: `wsl-api-bridge.test.py` checks alternate methods, absolute URLs and protocols, proxy headers, OS principal, frame ambiguity, auth-file replacement, response header injection, concurrency, request/byte/output reservations. `wsl-worker-isolation.test.py` runs the real Linux Codex 0.163.0 against a fake endpoint and an actual stdio MCP descendant inside isolated bwrap; it checks non-API/proxy requests, direct external TCP, auth-file absence, and protected-file denial. An authenticated turn has been exercised separately but is **not** authorization for production dispatch. The bridge has no independent controller claim lifecycle, gate/git/TDD/settle or reviewer verification; `codex-cli` preflight remains DENY pending integration and independent adversarial acceptance. Never infer that an MCP tool's success or Codex `turn.completed` establishes those gates.
