# Experimental WSL claim-input and proposal transport contract

This is a launcher transport prototype, **not broker authorization or production dispatch**. The existing Codex preflight remains disabled. The trusted root launcher receives a controller-authored root-owned, private, explicit source-file manifest; it copies selected regular-file bytes through pinned directory handles into a new root-owned per-launch snapshot, mounted read-only at `/work`. Dotfiles, special files and symlinks are excluded/rejected; bounded files are copied, never hardlinked into the worker mount. `stat`/`fstat` identity and metadata checks reject observed replacement or mutation during a file read. Those checks are not an atomic snapshot of a concurrently writable source tree: the controller must freeze source updates or supply an immutable source tree before launch. The worker and descendants receive only a separate, worker-owned proposal directory at `/proposal`, not a writable bind of the source or any protected result inode.

`--transport-dir <absolute-root-owned-private-directory>` is an alternative to the legacy experimental `--report <path>` (mutually exclusive). Its root and ancestors cannot be symlinks; its private root must be mode 0700. Claim and generation tokens consist only of ASCII letters, digits, `_` and `-` (1–100 characters). A claim/generation directory is created or opened under pinned `O_NOFOLLOW` directory descriptors. Before sandbox launch, the launcher exclusively creates and fsyncs `<role>.pending`, recording claim, generation and role. **A pending file is an irrevocable reservation**; a failed, killed or interrupted run must never reuse that generation/role. Recovery uses a fresh generation after terminating/reaping the old process tree. A fully validated worker exit produces fsynced `<role>.json` via an exclusive temporary file and hardlink publication, then fsyncs the slot directory; the pending marker remains as an audit marker. An orphan `<role>.tmp` or pending-only slot is not a success. Only root can access the transport. The isolated worker cannot name, mount, modify, or replace it.

The JSON envelope is `{claim, generation, role, source_files, proposals, submission}`. `proposals` is a map of bounded relative paths to UTF-8 contents; `submission` is an optional JSON object extracted from the role-specific `result.json` or `verdict.json` proposal file. It is untrusted worker output, not a sealed result, reviewer verdict, or grant of path authority. The consuming broker must independently check its authenticated peer identity, active claim/generation, allowed paths and owner role, validate the envelope and proposal content, then seal separate role-owned output slots and journal/reconcile any application. **Never accept a JSON envelope solely because its filename or self-reported role matches.** Never treat pending-only, temporary, stale, partially published or ambiguous generations as accepted. The broker implementation/authorization and Orchestrator claim integration are outside this slice.

The `--report` compatibility mode remains for existing standalone tests, not the private persistent contract. Neither mode activates native Windows or WSL Codex production dispatch. The source root, controller/root launcher, and provisioned transport path are trusted inputs; a malicious controller/root process or a concurrently mutable source tree is not isolated by this worker boundary.
