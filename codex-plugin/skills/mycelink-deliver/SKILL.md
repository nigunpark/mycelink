# Codex deliver: reviewed continuation

Resolve `<plugin-root>/bin/mycelink.mjs` from **this skill's absolute SKILL.md path** (`skills/mycelink-deliver/SKILL.md` under that root), verifying the launcher and bundled runtime. Never use PATH, cwd/source or Claude assets. **Standalone `codex deliver` remains denied**; do not bypass with generic `deliver`, `candidate`, `settle`, `orchestrate` or direct `codex exec`. The supported experimental delivery path is `codex continue <feature-id> --review --deliver --max-nodes <1-8> --max-reviews <1-6> --control-root "<absolute-control>" --json` for a fresh control or continuation of an existing valid controller, with an approved PRD/graph and explicit `experimental_codex.enabled: true` plus every registered repository in `experimental_codex.disposable_repositories`. Never opt in a production checkout. It retains one controller authority through workers, independent review, candidate and post-delivery verification. For a fresh candidate it delivers only after PASS; GAPS, exhausted bounds, failed tests or a stale candidate are not delivery. Read back the delivered base's exact Git HEAD, candidate binding and independent post-delivery test receipts before reporting success. When authority exists, continuation verifies the prior holder identity and proves its PID has exited before engine-checked recovery under the lock; active or unverifiable holders fail closed. Do not supply `--authority`, `--recover` or `--takeover`, copy authority, or bypass review. Standalone `codex resume` remains denied; generic `dispatch` and `session` are also unavailable as bypasses.

If process loss occurs after a built candidate was pinned following a prior PASS, rerun the same `codex continue <feature-id> --review --deliver --control-root "<absolute-control>" --json` to resume delivery without a second review or replacement worker dispatch. The finalizer requires the review gate to pass, a required acceptance review with prior PASS, all nodes DONE or EXCLUDED, a DONE candidate-build node and VERIFIED feature state. It verifies the pinned candidate against control and repository refs and checks feature verification before delivery with post-delivery tests. Drift or invalid evidence fails closed; an already accepted delivery is rejected as replay.
