# Codex run: bounded experimental continuation

Locate the packaged launcher from **this skill's absolute SKILL.md path**, ascending from `skills/mycelink-run/SKILL.md` to the plugin root. Verify `bin/mycelink.mjs` and `dist/mycelink.mjs` there; never resolve a PATH/cwd/source/Claude launcher. Require an approved PRD with CLI-created ACCEPTANCE.json, an operator-reviewed graph that validates, registered disposable Git repositories, and the operator's explicit `experimental_codex.enabled: true` plus every repository name in `experimental_codex.disposable_repositories`. Never opt in a real production checkout. Planning commands need no controller key: do **not** run `controller open` or `feature init` before a fresh continuation.

For a fresh control or continuation of an existing valid controller, run `node "<plugin-root>/bin/mycelink.mjs" codex continue <feature-id> --max-nodes 8 --max-reviews 6 --review --deliver --control-root "<absolute-control>" --json` for a bounded PRD-to-delivery attempt. This one process opens or safely recovers and retains authority, initialises the validated graph only if state is absent, executes sequential Codex worktree workers, separately reviews the result, and after PASS builds a candidate and delivers with post-delivery tests. An already built candidate follows the prior-PASS recovery checks described in mycelink-deliver without a second review. Bounds are total worker invocations (1–8) and reviews (1–6), including separate refinement reviews; they do not guarantee completion. Omit `--deliver` to review without delivery or omit both review flags for a worker-only cycle. A nonzero exit or GAPS is not completion; inspect each node's real RED/GREEN receipts, test/source commits, review revisions and delivered SHA. For existing authority, continuation verifies the recorded prior holder identity and proves its PID has exited before requesting engine-checked recovery under the lock; an active or unverifiable holder fails closed. Do not supply `--authority`, `--recover` or `--takeover`, copy authority, or bypass review. A host holding a key may use `codex run` for one cycle but must retain custody. Standalone `codex resume` and `codex deliver` remain denied. Never bypass denial with direct `codex exec` or generic `dispatch`, `session`, `orchestrate`, `candidate` or `deliver` commands.
