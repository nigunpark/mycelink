# Codex run: bounded experimental worker cycle

Locate the packaged launcher from **this skill's absolute SKILL.md path**, ascending from `skills/mycelink-run/SKILL.md` to the plugin root. Verify `bin/mycelink.mjs` and `dist/mycelink.mjs` there. Do not search PATH, cwd, source checkout, or adjacent Claude assets; stop if missing. Require a separately initialized Codex control, approved PRD and validated graph; the operator must explicitly configure `experimental_codex.enabled: true` and list **every** registered disposable Git repository under `experimental_codex.disposable_repositories`. Do not set this opt-in yourself or use real production repositories. For a **fresh control without existing controller authority**, run `node "<plugin-root>/bin/mycelink.mjs" codex continue <feature-id> --max-nodes 2 --control-root "<absolute-control>" --json`. This opens and holds authority in one host process, initializes the approved graph if needed, and invokes at most two sequential nodes, stopping on a failed or missing node; it does not review or deliver. Never invoke it against a control with an existing key: it refuses to recover, take over or copy that key. A host already holding an authority key may use `codex run <feature-id> --authority <key>` for one cycle only, but must retain custody to continue. On a preflight denial, stop; never bypass using direct `codex exec` or generic runtime commands. Check each node state, actual RED/GREEN evidence and Git commits; a completed process is not proof of acceptance. Reviewer, verification and delivery remain disabled in this slice.
