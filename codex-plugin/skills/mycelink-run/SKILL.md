# Codex run: bounded experimental worker cycle

Locate the packaged launcher from **this skill's absolute SKILL.md path**, ascending from `skills/mycelink-run/SKILL.md` to the plugin root. Verify `bin/mycelink.mjs` and `dist/mycelink.mjs` there; never resolve a PATH/cwd/source/Claude launcher. Require an approved PRD with CLI-created ACCEPTANCE.json, an operator-reviewed graph that validates, registered disposable Git repositories, and the operator's explicit `experimental_codex.enabled: true` plus every repository name in `experimental_codex.disposable_repositories`. Never opt in a real production checkout. Planning commands need no controller key: do **not** run `controller open` or `feature init` before a fresh continuation.

For a **fresh control with no controller authority**, run `node "<plugin-root>/bin/mycelink.mjs" codex continue <feature-id> --max-nodes 8 --max-reviews 6 --review --deliver --control-root "<absolute-control>" --json` for a bounded PRD-to-delivery attempt. This one process opens and retains authority, initialises the validated graph, executes sequential Codex worktree workers, separately reviews the result, and only after fresh PASS builds a candidate and delivers with post-delivery tests. Bounds are total worker invocations (1–8) and reviews (1–6), including separate refinement reviews; they do not guarantee completion. Omit `--deliver` to review without delivery or omit both review flags for a worker-only cycle. A nonzero exit or GAPS is not completion; inspect each node's real RED/GREEN receipts, test/source commits, review revisions and delivered SHA. Never invoke against a control with an existing key or attempt recovery/takeover/copy of a closed authority. A host holding a key may use `codex run` for one cycle but must retain custody. Never bypass denial with direct `codex exec` or generic runtime commands.
